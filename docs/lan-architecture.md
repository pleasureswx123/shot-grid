# 局域网多人架构

## 目标拓扑

```text
员工浏览器
    │ HTTP / 内部 HTTPS
    ▼
ShotGrid Light 服务端
    ├── React 静态前端
    ├── Express API
    ├── 会话与权限检查
    └── 文件访问控制
          │
          ├── PostgreSQL（业务数据、会话、审计）
          └── NAS / 对象存储（视频、图片、工程文件）
```

PostgreSQL 和 NAS 不直接暴露给员工浏览器。所有写操作经过 API，由服务端完成身份、项目成员和角色权限检查。

## 已完成的基础

- 单端口 Express + Vite 开发服务器；
- 生产环境静态文件托管；
- PostgreSQL 连接池和串行迁移；
- 首位管理员安全初始化；
- scrypt 密码哈希；
- 随机会话令牌，数据库仅保存 SHA-256 会话摘要；
- HttpOnly、SameSite Cookie；
- 登录频率限制、同源写请求检查和登录审计；
- 完整首版领域表结构。
- 前端登录、会话恢复和退出登录；
- 管理员员工账号界面与用户管理 API；
- 项目创建、项目列表和项目成员 API。
- 前端首次项目创建、多项目切换和真实成员管理；
- 服务端项目已成为当前项目元数据的事实来源，旧本地项目数据不再覆盖它。

## 迁移顺序

### 1. 账号与项目成员

真实登录、用户管理、项目创建/选择和成员管理已完成。后续仍需完善账号停用和密码重置。

### 2. 镜头、资产和任务

下一阶段将 `AppContext` 中的新增镜头、资产、任务状态及 Excel 导入迁移成事务 API。服务端负责唯一编号和管线依赖，避免多人同时操作导致冲突。

### 3. 版本、文件和审核

实现分片上传、NAS/对象存储适配器、版本提交、审核单、批注和状态机。禁止把大型 Data URL 写入数据库。

### 4. 实时协作

通过 WebSocket 或 SSE 推送任务、版本、评论和审核状态变化。数据库仍是最终事实来源。

### 5. 运维

增加自动备份、恢复演练、日志轮转、内部 HTTPS、健康监控和升级回滚流程。

## 权限原则

- `admin`：用户、项目、系统配置和审计；
- `director`：项目管理、任务分配、审核和锁版；
- `creator`：查看所属项目、更新任务、提交版本和回复意见；
- `client`：仅查看被授权内容并提交审核意见。

按钮隐藏只能改善界面体验。所有权限必须在 API 服务端再次验证。
